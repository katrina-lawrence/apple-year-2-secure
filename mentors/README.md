
# Year 2 — Mentor Resources

Welcome to the Year 2 Cybersecurity Program mentor resources.

This directory contains the guides, technical instructions, and supporting materials needed to prepare for and support Module 1 delivery.

## Start Here

Before the program begins:

1. Review the **Mentor Training & Module 1 Delivery Guide** to understand the learning objectives, daily challenges, mentor responsibilities, and expected outcomes.
2. Complete the preparation steps in the **Technical Setup Guide**.
3. Confirm access to the application and backend repositories.
4. Verify the required development tools, application branches, backend configurations, and reference implementations.
5. Review the daily instructor guides and student materials before each workshop.

## Daily Preparation

Before each workshop, mentors should:

- Confirm the correct application and backend branches.
- Verify that the starter application builds and launches.
- Test backend connectivity where required.
- Prepare and test reference implementations.
- Confirm that required datasets, tools, and test accounts are available.
- Review the day's challenges and expected outcomes.
- Identify potential technical issues and available workarounds.

Refer to the **Technical Setup Guide** for detailed instructions.

## Supporting Learners

During delivery, mentors should:

- Help learners investigate technical issues.
- Encourage independent problem-solving.
- Ask guiding questions rather than provide completed solutions.
- Support testing, debugging, and interpretation of results.
- Help learners document evidence and explain their decisions.
- Escalate issues that prevent progress or affect multiple learners.

## After Each Workshop

- Record recurring technical issues and workarounds.
- Capture common learner questions and challenges.
- Share relevant observations with the instructional team.
- Confirm readiness for the next workshop.

## Important Notes

- Use only approved lab credentials and fictional test data.
- Do not commit API keys, passwords, or sensitive configuration files.
- Keep mentor reference implementations separate from student starter materials.
- Follow the approved repository versions and technical instructions.
- Report unresolved technical issues through the agreed support channels.
